## Introduction to Object-Oriented Programming

Object-oriented programming models software entities as **objects** that combine state (data stored in member variables) with behavior (member functions that query or modify that state).

Core OOP concepts in C++:
- **Encapsulation / Information hiding:** Member variables are typically kept `private`; a `public` interface of member functions controls all access. This allows the internal implementation to change without breaking code that uses the class.
- **Instances and classes:** A `class` defines a type. An **object** is a concrete instance of that type, living in memory.
- **Class hierarchies:** Classes can inherit from other classes, capturing shared behavior in a base class and specializing it in derived classes.

## Declaration and In-place Definition

A class is **declared** by specifying its member variables and the signatures of its member functions. It is **defined** when those member functions are implemented. Both can happen in the same block.

Classes declared in **global scope** are available everywhere in the translation unit. Classes declared in **local scope** (e.g., inside `main`) are restricted to that scope.

```cpp
#include <iostream>

// Global scope: dfloat is available everywhere below
struct dfloat {
    // Member variables with default initialization
    float _v{0};       // value, initialized to 0
    bool  _d{false};   // dependency flag, initialized to false

    // Member function defined in-place (inline)
    void make_dependent() { _d = true; }
};

int main() {
    dfloat x;              // allocates a dfloat object on the stack
    x._v = 42.0f;          // direct member access via dot operator
    x.make_dependent();    // calls the member function on x

    std::cout << x._d << "\n";  // 1  (true)
    return 0;
}

void f() {
    dfloat y;  // valid: dfloat is in global scope, accessible here
    // y._v == 0, y._d == false
}
```

If the class is declared inside `main`, it is **not** accessible in `f`:

```cpp
int main() {
    struct local_type { int x{7}; };  // only visible inside main
    local_type a;
    // a.x == 7
}

void f() {
    // local_type b;  // ERROR: 'local_type' was not declared in this scope
}
```

## Allocation of Objects

Class instances can be allocated either on the **stack** (automatic storage, `dfloat x;`) or on the **heap** (dynamic storage, `new dfloat()`).

```cpp
#include <iostream>

struct dfloat { float _v{42}; };

int main() {
    // Stack allocation: lifetime is automatic (ends when scope exits)
    dfloat x;
    std::cout << x._v << "\n";      // 42

    // Heap allocation: lifetime must be managed manually
    dfloat* p = new dfloat();
    std::cout << p->_v << "\n";     // 42
    std::cout << (*p)._v << "\n";   // 42  (equivalent to p->_v)

    delete p;  // REQUIRED: release heap memory or you have a memory leak

    // Classes can also appear in arrays and standard containers
    dfloat arr[3];                   // static array of 3 dfloats on stack
    dfloat* arr2 = new dfloat[3];    // dynamic array of 3 dfloats on heap

    std::cout << arr[0]._v << "\n";  // 42
    delete[] arr2;                   // use delete[] for arrays
}
```

## Default Constructor

A **constructor** is a special member function called automatically when an object is created. The **default constructor** takes no arguments. It is generated by the compiler automatically — *unless* you declare any custom constructors, in which case you must explicitly request it with `= default`.

```cpp
#include <iostream>

struct dfloat {
    float _v{42};   // default initialization value
    bool  _d{false};

    dfloat() = default;  // explicitly request compiler-generated default constructor
                         // (optional here since no other constructors exist,
                         //  but REQUIRED if a custom constructor is also declared)
};

int main() {
    dfloat x;                       // default constructor is called
    std::cout << x._v << "\n";      // 42  (from the in-class initializer)
    std::cout << x._d << "\n";      // 0   (false)
}
```

## Custom Constructors

**Custom constructors** let you initialize objects with specific values at creation time. Parameters are listed like a regular function, and member variables are initialized in a **member initializer list** (the `: member{value}` syntax after the parameter list).

If a custom constructor is declared, the compiler **no longer generates** the default constructor automatically. You must declare it explicitly with `= default` if you still want it.

```cpp
#include <iostream>

struct dfloat {
    float _v;   // no in-class initializer this time
    bool  _d;

    // Custom constructor: initializes _v and _d from arguments
    dfloat(float v, bool d = false) : _v{v}, _d{d} {}
    // Note: the empty {} body means no additional setup is needed

    // Since a custom constructor exists, the default constructor
    // is NOT auto-generated — we must request it explicitly:
    dfloat() = default;
    // But without in-class initializers, _v and _d will be uninitialized
    // when this default constructor is used! Better practice:
};

// Better version with both constructors and safe defaults:
struct dfloat2 {
    float _v{0};      // safe fallback
    bool  _d{false};  // safe fallback

    dfloat2(float v) : _v{v} {}  // custom: sets _v, _d stays false
    dfloat2() = default;          // default: uses in-class initializers
};

int main() {
    dfloat2 y(3.14f);  // calls custom constructor
    std::cout << y._v << "\n";  // 3.14
    std::cout << y._d << "\n";  // 0   (false, from in-class initializer)

    dfloat2 z;           // calls default constructor
    std::cout << z._v << "\n";  // 0   (from in-class initializer)
}
```

## Default Destructor

The **destructor** is called automatically when an object leaves its scope (stack object exits block, or `delete` is called on a heap object). For simple structs with no heap-owned memory, the compiler-generated default destructor is sufficient.

```cpp
#include <iostream>

struct dfloat {
    float _v{42};

    ~dfloat() = default;  // compiler-generated: just pops the stack frame
    // For a struct owning heap memory, you would write a custom destructor here
};

int main() {
    {
        dfloat x;
        std::cout << x._v << "\n";  // 42
        // x goes out of scope here → ~dfloat() is called automatically
    }
    // x no longer exists here
    return 0;
}
```

For classes that **allocate dynamic memory** in their constructor, the destructor must release it:

```cpp
#include <iostream>

class dfloat_array {
    float*  _v;
    size_t  _s;
public:
    // Constructor: allocates and initializes dynamic array
    dfloat_array(size_t s) : _v{new float[s]}, _s{s} {
        for (size_t i = 0; i < _s; ++i) _v[i] = float(i) * 1.5f;
    }

    void print() const {
        for (size_t i = 0; i < _s; ++i)
            std::cout << _v[i] << " ";
        std::cout << "\n";
    }

    // Custom destructor: releases the heap memory
    ~dfloat_array() {
        delete[] _v;  // without this, memory leaks every time an object is destroyed
    }
};

int main() {
    dfloat_array arr(4);
    arr.print();  // 0 1.5 3 4.5
    // ~dfloat_array() called automatically here, delete[] _v executes
}
```
